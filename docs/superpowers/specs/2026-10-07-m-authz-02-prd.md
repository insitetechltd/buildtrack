# M-AUTHZ-02 PRD — Multi-company project membership

**Status:** Locked for return (2026-10-07). Not started.  
**Milestone:** `WS-AUTHZ / M-AUTHZ-02`  
**Product law:** `documentation/multi-company-project-membership.md`  
**Already shipped:** `M-AUTHZ-RC` (host-company roles), `M-REPORT-01` (report close)  
**Human Gate:** schema, invite tables, liaison grant, seat-payer column, inter-company comment storage, and row-level security wait for a written go-ahead.

Same-company roster, invite, Project Admin, and report close stay as they are. Partner liaison, project invite, host-absorb, and the close notice plus one comment are added only where another company is involved.

## Problem

A host company runs the job. A partner company sends the crew. The app is built for one company on its own projects. Putting a partner on the job either spends the host’s seats or means browsing people outside the company. A host manager can close a partner worker’s report, and after that the worker cannot answer. Both sides need the same unaltered record. A host manager closing a host worker’s report must keep working exactly as it does today.

## Who it is for

The host Project Admin runs the host roster and is the only person who may appoint a liaison, send a host project invite, or bill a seat to the host. The partner liaison adds and removes that partner’s own people on that one job. A worker files reports. When a manager from another company closes one, the filing worker is told and may add one comment. A company admin can see which of their own people are on which jobs. On their own company’s jobs, their powers stay as they are.

## Outcome

A person from Company B can be on Company A’s project without joining Company A and without appearing in a global directory. Company B pays for that person unless a host Project Admin explicitly takes the seat. When a manager from one company closes a report filed by someone in another company, that filer is told and may add one final comment. The close is already final. When both people are in the same company, the close is the one already shipped, with no notice and no later comment.

## Same-company behavior, unchanged

This is the oracle. On a job with only one company, and for any two people of the same company even when a partner is also on the job, the app behaves as it does today.

- Company admin, project manager, worker, and one host Project Admin stay as they are. Project Admin stays a host grant. A company admin does not become a project manager by holding that office.
- Adding someone from your own company stays the host Project Admin roster action. Company seat invite (`inviteCompanyUser`) stays an in-company seat invite. The host seat meter behaves as it does today.
- A report close stays the close already shipped. A typed note is required. Photos stay with that note. An empty field does not close and does not upload.
- A manager close stores “Issue resolved by {name}: Resolved with reply,” plus the note and its photos. The worker is not notified. There is no badge on Tasks → Outbox. After close the dock is Archive. There is no further comment.
- A worker’s own close stores “Issue acknowledged and closed by {name},” plus their note. It does not grant another comment.
- Who can open a report stays as it is. A worker sees a report they filed or are assigned to. A host manager sees the team report. Another member on the job does not gain reports they cannot open today.
- Ownership moves only when the manager promotes the report into a task.
- Removing someone from the project removes their access the way it does today.
- The team row on a one-company job stays as it is. A company name is not added to those rows.

## What inter-company adds

### Path A — Partner liaison

The host Project Admin appoints one active liaison per partner company per project. The partner company is one company already on the platform, named by the host. The person is one email. The appointment succeeds only when that account’s company is the named partner. The host is told success or failure. The host is not shown that company’s roster.

If someone from that partner is already on the project, the host Project Admin may appoint one of those people instead of typing an email. The same company check applies.

The liaison is a member of their own company on this project. The grant is not host Project Admin. A partner person is never given host Project Admin.

The liaison adds and removes people from their own company on this project, from their own company’s list. Those adds use the partner company’s existing seat meter and refuse when that meter is full, the same way a host add refuses when the host meter is full. The host meter does not move. The host does not keep the partner roster day to day.

The host Project Admin can replace the liaison by the same named-email or already-on-project rule. After replacement, the previous liaison cannot add or remove.

The host’s own roster action is unchanged.

### Path B — Project invite

The host Project Admin, or that partner’s liaison, sends a project-scoped link to one named email. A liaison may invite only an email that already belongs to their own company. A host Project Admin names one company already on the platform and one email. The invite succeeds only when that email’s company is the named company, or when the email is new and the named company is the company they will join. The host is not shown a roster.

The invite stores the project, the named email, the named company, a token, expiry, the inviter, intended role **member**, and billing path B. Accept creates one assignment on that project only, as a member, not as Project Admin.

Accept succeeds only for an authenticated account whose email matches the invite. A different person opening the link does not get the assignment. An expired or revoked link does not create an assignment. Seats stay on the named company and use that company’s existing seat meter. Accept is refused when that meter is full. The host meter does not move.

Until accept, the person is not on this project’s team. The pending invite is visible to the inviter and to the host Project Admin on that project. It is not in any picker.

### Path C — Host absorbs the seat

Same invite and accept as Path B, except the billing company is the host. Only a host Project Admin may select “bill to our seats.” A liaison cannot. The person stays in their own company. Accept does not move them into the host company.

The host’s existing seat meter is what “counts against the host” means. Accept is refused when that meter is full. The partner meter does not move. A company-admin seat still does not count as a jobsite seat. Plan prices stay as they are. Nothing absorbs a seat silently.

The count starts at accept and stops when that person is removed from the project.

### Company-admin knowledge

A company admin can see which of their own people are on which projects, including a job owned by another company. The list is the person’s name and the project’s name. Opening the job still requires an assignment. On their own company’s jobs, their existing powers are unchanged.

### Team list and pickers

When a job has more than one company, this project’s team shows accepted members, host and guests, with each person’s company, after accept only. On a one-company job the team row is unchanged.

Add-from-company shows the viewer’s own company, plus people already assigned to this project. An accepted guest appears in this project’s already-assigned set. They do not appear in any other project’s company picker and they do not appear in a platform-wide list.

Create, edit, triage, and delegation follow that rule. On a one-company job the people offered are still that company’s own people, through the same Project Admin action as today. There is no new confirm step. What goes away is choosing someone from another company out of a platform-wide list. That path is the project invite.

### Report close record

This is only when the manager and the filing worker are not in the same company. A same-company close, including on a mixed job, is the unchanged close above. It writes no notice and offers no later comment.

The set of people who may close a report stays as it is today. Company difference does not add a closer and does not remove one.

- The manager’s close is the close, under the rules already shipped. Status becomes resolved then. The worker being offline or silent does not hold the report open and does not erase the close time. An empty text field still does not resolve.
- The filing worker is told on the report itself and on Tasks → Outbox, which is where a report they filed already appears because they are the one who filed it. The notice is still there the next time they open the app. It is not a toast that disappears. It names the closer and shows the line that close already stored: “Issue resolved by {name}: Resolved with reply,” the note, and its photos. A same-company close does not write this notice. A phone push is not required.
- The filer may then add exactly one comment on that resolved report. The comment requires text. It can be an objection, an acceptance, or a liability note. It carries their name, time, and company, and an optional photo. A photo with no text does not use up the comment.
- Only the filer may write it. The manager, a liaison, and anyone else are refused. The row cannot be edited or deleted. It does not change status, assignees, or `assigned_by`. It does not reopen the report and does not start a thread. The manager does not have to answer. The close row and the close time stay as written.
- If they never write it, the close still stands. People who can already open that report then see only the manager’s row.
- Who can open the report stays who can open it today. The two rows do not become visible to every member of the project. A company admin without an assignment does not get the report from the knowledge list.
- A worker’s own close, in either company, stays the shipped self-close and does not gain another comment.
- If the liaison later removes that filer from the project, the filer keeps read access to reports they filed and keeps the one unused comment on those reports. They do not gain the rest of the job. A same-company removal does not gain this retention.

Ownership still moves only when the manager promotes the report into a task.

## Out of scope

- Any change to same-company roster, company invite, Project Admin, team-row layout, report visibility, or same-company report close.
- A notice or a post-close comment on a same-company close.
- Accept waiting on a partner company admin. A later non-blocking notice to that admin is still allowed.
- A global people directory, a company roster for the host, or cross-company name search.
- Silent host billing, or moving a Path C person into the host company.
- Giving a guest or a liaison host Project Admin.
- Reopening a closed report, or a reply thread after the final comment.
- Holding any close until the worker comments.
- Owner HQ, on-site Q&A, drawings, and daily-report build.
- Changing plan prices in the Stripe catalog.

## Human gate

Schema, invite tables, the liaison grant, the seat-payer column, the inter-company comment, and row-level security are not applied until there is a written go-ahead. Before that go-ahead, the inter-company close record can be built and tested against the close already shipped. Paths A–C, picker isolation, and seat counts are not accepted until those tables exist and are proved on the destination database.

## Acceptance

1. On a one-company job, adding your own people, company invite, Project Admin, the team row, who can open a report, and report close match the current app. A same-company manager close does not notify, does not badge Outbox, and does not offer a comment after close. A same-company removal still drops access as it does today. This remains true for two people of the same company on a job that also has a partner.
2. A host Project Admin names one existing partner company and one email. The liaison appointment succeeds only when that account’s company is the named partner, and the host sees no roster. They can replace that liaison. The replaced liaison cannot add or remove. A second active liaison for that pair cannot exist. The liaison is not host Project Admin. The host’s own roster action is unchanged.
3. A liaison add or a Path B accept uses the partner company’s existing seat meter and is refused when that meter is full. The host meter does not move. A host add of the host’s own people still uses the host meter as it does today.
4. A project invite creates no membership until the matching account accepts, before expiry. After accept they are a member on that project only, billed to the company on the invite, and they show on this project’s team with their company. A different email opening the link gets nothing. A one-company job’s team row is unchanged.
5. Only a host Project Admin can select “bill to our seats.” That accept uses the host seat meter and is refused when the meter is full. The person stays in their own company. A liaison cannot select it.
6. A company admin’s outbound list is names and project identity. It does not open another company’s job. Their powers on their own jobs are unchanged.
7. Create, edit, triage, delegation, and team add do not offer a platform-wide list and do not search across companies. A one-company add still offers that company’s own people and adds no new step.
8. A host manager closes a partner worker’s report with a note. The partner worker sees the closer’s name and “Issue resolved by {name}: Resolved with reply,” plus the note and photos, on the report and on Tasks → Outbox. They can add one text comment with an optional photo. Status and close time stay. A second comment, an empty comment, and anyone else’s comment are refused. People who could already open that report see both rows, or only the manager’s row if the filer writes nothing. A member who could not open that report still cannot.
9. A host manager closes a host worker’s report on that same mixed job. There is no notice, no Outbox badge, and no comment after close.
10. The filer closing their own report still requires a note and does not gain an extra comment.
11. Closing the partner report while the filer has no network still leaves it resolved with a close time. The notice is on the report and on Outbox at their next open, and the one comment is still available.
12. A partner worker removed after that close can still open reports they filed and, if unused, add the one comment. They cannot open the rest of the job. A same-company removal does not gain that retention.
