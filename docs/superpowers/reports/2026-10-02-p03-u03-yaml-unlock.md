### P03-BLOCKER

**Symptom:** After accepting reopen picks (slots 1+2), Select Photos showed only `photo-selection__tile_0` and `tile_1`. Assert for `tile_2` failed.

**Root cause:** Reopen-from-form behavior — selection screen shows only **newly added** photos. Prior attachment (from first `_open-library`) stays on form. After `_confirm-selection`, all 3 attachments merge on form.

**Fix:** Move assert from selection screen to form (after confirm):
```yaml
# Before (line 30 — FAIL)
- assertVisible:
    id: "photo-selection__tile_2"

# After (line 31 — after confirm)
- assertVisible:
    id: "create-task__attachment_preview_2"
```

### U03-BLOCKER

**Symptom:** After "Add more → Choose from Library", hierarchy showed `in-app-library__screen` and `in-app-library__grid`. Helper asserted `capture-session__hybrid_library` → FAIL.

**Root cause:** Update Progress add-more path opens **legacy InAppLibrary**, not hybrid CaptureSession. Helper `_reopen-library-from-selection` (borrowed from create-task) expects hybrid.

**Fix:** Create update-progress-specific `_reopen-library-from-selection.yaml` that accepts `in-app-library__*`:
```yaml
- tapOn: "Choose from Library"
- extendedWaitUntil:
    visible:
      id: "in-app-library__screen"
    timeout: 15000
- extendedWaitUntil:
    visible:
      id: "in-app-library__grid"
    timeout: 15000
```

U03 and U04 now use local helper instead of `../create-task-photo/_reopen-library-from-selection.yaml`.

## Rationale by Fix

### P03: Selection vs Form Tiles

**Phase B behavior (reopen-from-form):**
- Initial `_open-library` → 1 photo → goes to **form** with 1 attachment
- Reopen from form → pick 2 more → accept → **selection screen** with **2 tiles only** (the new picks)
- Confirm selection → **form** now has **3 attachments** total

**Contrast with P03-library-only:**
- All 3 picked in **one** library session
- After accept → selection screen shows **all 3 tiles**
- Different flow pattern

**Fix:** Assert tile_2 on form after confirm, not on selection after accept.

### U03/U04: Legacy vs Hybrid Library Path

**Update Progress add-more route:**
- Opens **legacy InAppLibrary** (`in-app-library__screen` + `in-app-library__grid`)
- Does NOT open hybrid CaptureSession

**Create Task add-more route:**
- Opens **hybrid CaptureSession** (`capture-session__hybrid_library`)

**Fix:** Create update-progress local helper that matches actual route (in-app-library).
